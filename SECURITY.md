# Security policy

## Supported versions

Security fixes are applied to the current `main` branch. This project has not
yet published a stable release series with long-term support guarantees.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub's **Report a vulnerability** action on the repository Security page
to send the maintainers a private report. If that action is unavailable while
the repository is private, contact the repository owner through the contact
method on the owner's GitHub profile and ask for a private reporting channel.

Include:

- the affected file, feature, or revision;
- steps to reproduce or a proof of concept;
- the likely impact;
- any suggested mitigation; and
- whether the issue is already public.

You should receive acknowledgment within seven days. Please allow reasonable
time for validation and a coordinated fix before disclosure.

## Scope notes

This is a client-side static application. Reports about exposed credentials,
unsafe HTML rendering, malicious asset handling, dependency vulnerabilities,
or deployment configuration are in scope. Gameplay balance and ordinary bugs
belong in the public issue tracker.
